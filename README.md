# Unicode 规范化碰撞工作台

单机 Rust 工作台，用于在身份标识符规则迁移前审计哪些原文会得到相同规范化值。页面只作为服务端规则的可见入口；规范化、脚本、冲突、迁移与持久化判断都在服务端完成。

## 运行

```sh
cargo fetch
cargo test --quiet
cargo run --bin server -- --listen 127.0.0.1:5213
```

打开 <http://127.0.0.1:5213>。默认数据目录是 `data/unicode-workbench`，可用 `--data-dir` 覆盖。

## 模型与阶段

- 原文永不被覆盖：文本、原始 Base64 字节或显式码点序列分别保存；任何结果都作为新阶段或迁移版本存在。
- 阶段固定为 `source`、初次 NFC/NFKC、大小写折叠、默认可忽略字符处理、最终 NFC/NFKC。页面可按阶段筛选并展开 `U+XXXX`。
- 非法 UTF-8、Unicode 非字符码点、单独代理和混合脚本风险分别报告；有阻断问题的记录不进入最终桶。
- 同桶只是“冲突候选”。系统不会自动挑选一条删除，也不会把视觉相似字符视为等价。
- 脚本属性使用 `Common`/`Inherited` 以外的脚本集合识别混合风险；可配置单脚本或允许脚本清单。

规则表通过 ICU4X 的编译数据提供：ICU4X 1.5.x 对应 Unicode 15.1.0，ICU4X 2.3.x 对应 Unicode 16.0.0。创建方案时保存来源规则和目标规则快照；已批准方案之后不会因 Unicode 表升级而重算。比较版本差异需要创建新方案。

## 迁移

冲突组支持三种决定：

- `rename`：为记录指定新目标值；目标值仍按目标规则规范化，并可选择保留旧别名。
- `keep-alias`：指定一个主记录，组内旧值作为别名保留。
- `reject`：拒绝该冲突组迁移，其他组仍可按方案处理。

批准时检查：每组必须有决定、重命名不能产生新碰撞、别名图不能成环。非法状态跳转返回 409。应用时重新做全有或全无模拟；若批准基线后新增记录导致碰撞，提交不会写入任何迁移，并返回基线版本、当前版本和新增记录差异。

## 持久化与并发

- `events.jsonl` 是追加式事件日志；每次写入在一行 JSON 后 `fsync`。启动时重放完整行，截断最后一条不完整记录，因此 SIGKILL/断电后已同步事件可恢复。
- 数据目录用进程级 `flock` 防止两个服务器同时打开同一目录；硬退出由操作系统释放锁。
- 数据集和方案都有版本号。落后提交返回 409，并带当前版本、提交版本和服务端当前对象/记录差异，不做静默覆盖。
- `Idempotency-Key` 可包裹创建数据集、追加记录、创建/更新/批准/应用方案命令；同键不同请求体会返回冲突。

## HTTP API

- `POST /api/analyze`：按当前规则处理搜索查询，同时返回查询原文和规范化分析。
- `POST /api/datasets`、`POST /api/datasets/{id}/records`：创建集合或按版本追加。
- `GET /api/datasets/{id}/analyze?rules=...`：返回阶段、问题报告和最终桶。
- `POST /api/plans`：用 `from_rules` 与 `rules` 创建规则迁移方案。
- `POST /api/plans/{id}/decisions`：写冲突决定或请求 `approved`/`rejected` 状态跳转。
- `POST /api/plans/{id}/apply`：原子应用模拟。
- `GET /api/plans/{id}`：查看方案、源/目标分析和映射。
- `GET /api/plans/{id}/export`：确定性 JSON 导出，含规则快照、每条映射、决定和记录；包含 FNV-1a 64 位校验字段。

## 架构取舍

- HTTP 使用标准库手写小型 1.1 服务，避免把规则散到前端框架或引入大型 Web 框架；单机串行处理让版本冲突语义更直观。
- 持久化选择事件日志而不是直接覆盖数据库，便于崩溃恢复和审计“每次修订另存版本”。
- ICU 规则表编译进二进制，保证离线运行和确定性，但要升级 Unicode 版本必须重新构建程序。
- 导出不写墙钟时间，集合 ID 由名称和记录内容稳定哈希生成，因此相同输入/状态产生字节稳定输出。

## 限制

- 这是单机单进程工作台，不包含用户认证、权限、TLS、横向扩展或外部数据库。
- 手写 HTTP 解析器只支持常见 `Content-Length` 请求，不支持 chunked request、HTTP/2 或流式上传。
- 当前只提供 Unicode 15.1.0 与 16.0.0 两套表；没有在线下载自定义 UnicodeData。
- 视觉混淆检测（confusables）明确不参与等价判断，仅可以后作为独立风险提示扩展。
- FNV-1a 只用作确定性完整性/缓存标识，不声称抗碰撞密码学安全。
